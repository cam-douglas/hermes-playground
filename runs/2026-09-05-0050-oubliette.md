Title: `[BUG] Cowork Dispatch: child-completion notifications queue against an idle parent and only drain on the parent's next unrelated turn`. Labels: bug / has repro / platform:windows / area:cowork. Reporter AllyOmega (William Donahue).

Facts from the issue only:

- When a Dispatch child finishes, the completion notification is queued against the parent orchestrator and only delivered the next time that parent starts up for some unrelated reason (in practice, when the user sends it another message). Nothing wakes the parent on its own, so the delay is unbounded.
- Same parent saw delays of 1m44s, 12m06s, 48m34s and 11h35m. The last finished at 21:00 and was not relayed until 08:35 the next morning.
- Detection is immediate. Result, queue, and child's state change land in the same second:
  - `12:07:59 [info] [Result] Turn succeeded for session local_<CHILD>`
  - `12:07:59 [info] [Dispatch] Queued notification for cold parent local_ditto_<PARENT> (child local_<CHILD> completed)`
  - `12:07:59 [info] [Lifecycle] Session local_<CHILD>: running → idle`
- The queue drains only on the parent's `idle → initializing`:
  - `13:11:59 [info] [Lifecycle] Session local_ditto_<PARENT>: idle → initializing`
  - `13:11:59 [info] [Dispatch] Drained 1 queued notification(s) for local_ditto_<PARENT>`
- Two facts make the delay unbounded rather than just slow:
  - The parent is not listening while idle. Every wake relaunches the session process (`Starting local session local_ditto_<PARENT> in /home/<generated-name>` appears on each `idle → initializing`), so there is no process alive to receive a push.
  - The parent is idle nearly all the time, going `running → idle` a few seconds after each turn. Every completion in the log hit the cold path, 9 out of 9. The warm path never ran.
- No OS notification on this path. Nothing in the log emits one on child completion.
- The child cannot notify the parent itself. Per the `ccd_session_mgmt__send_message` contract it is "unavailable in unattended sessions (scheduled-task runs and remote-dispatched sessions), and cannot deliver to them either". A Dispatch child is remote-dispatched.
- Environment: Claude Desktop (Cowork / Code tab) 1.44121.4.0, MSIX. CCD 2.1.258. Windows 11 (10.0.26200) x64.
- Not a recent regression. The 48m34s case is on app 1.34493.0 / CCD 2.1.235 and the 11h35m case is on 1.44121.4 / CCD 2.1.258, with 1.37937.3, 1.40609.0 and 1.40609.1 in between, all behaving the same.
- Reporter's possible fixes (quoted, not claimed): wake the parent when a child completes and the parent is cold; at minimum, an OS notification on child completion independent of the parent's lifecycle.
- Hypothesis (non-binding): a Dispatch child completion is queued against the parent orchestrator; when the parent is idle there is no process alive to receive a push, so the notice sits until the next unrelated user turn.
