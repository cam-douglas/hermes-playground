Title: `[BUG] Drag & drop from the VS Code Explorer silently does nothing in Remote-WSL/SSH/Dev Containers — drop handler only accepts \`file://\` URIs`. Labels: bug, has repro, platform:windows, area:ide, platform:vscode, platform:wsl. Filed 2026-09-05T23:03:50Z. Updated 2026-09-05T23:04:53Z. Reporter: AndresDiagoM. Comments: none at ship time.

Facts from the issue only:

- Extension: `Anthropic.claude-code` **2.1.261** (also **2.1.259**); installed remote-side under `~/.vscode-server/extensions/anthropic.claude-code-2.1.261-linux-x64`
- VS Code: **1.136.1** (commit `a44adf7f53e00964ab890f9f8758a334f1fc15bc`)
- Client: Windows 11. Remote: WSL2 Ubuntu, kernel 6.18.40.1-microsoft-standard-WSL2
- Shift+dragging a file from the VS Code Explorer into the Claude Code panel does nothing when the window is connected to a remote (Remote-WSL, Remote-SSH, Dev Containers). No `@mention`, no attachment, no error. The same drag works in a local window.
- Cause: webview drop handler accepts only `file://` URIs; remote windows produce `vscode-remote://` URIs. Helper (`eG0` in 2.1.261, `OJ0` in 2.1.259) returns null unless the trimmed URI starts with `file://`. Drop discarded silently.
- Local Explorer hands over `file:///c%3A/Users/...`, which passes. Remote Explorer hands over `vscode-remote://wsl%2BUbuntu/home/user/project/src/app.ts`, which fails.
- `codeeditors` branch reads `q.resource.external || q.resource.fsPath`. `external` is the `vscode-remote://` string, so it also fails. Preferring `fsPath` (`/home/user/project/src/app.ts`) would have worked.
- Drag detection is scheme-agnostic (`Files` / `resourceurls` / `codeeditors`), so the overlay still appears and the failure looks like a no-op.
- Suggested normalize: map `vscode-remote://<authority>/<path>` to `file:///<path>` before existing logic. Local patch made drag & drop behave exactly as on a local window. Verified table in the issue (cwd `/home/user/project`).
- Workarounds: type `@` and pick; drag from Windows Explorer (`dataTransfer.files`); Copy Relative Path paste.
