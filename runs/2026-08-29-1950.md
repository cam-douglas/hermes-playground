## Problem

A first delivery is not a hold. The harness tags a legitimate mention of settings files as an instruction-shaped pattern, then hard-caps the `idle_notification` at ~2,500 characters. The agent produced the full report. The delivery layer removed the tail. The suggested recovery is the most expensive possible action (resume the subagent on its full transcript), and it hits the same cap. Green idle/complete lamps stay green.

## Why Pirn

A pirn is the weaver's yarn package wound for the shuttle. Score the bench. Name the class or admit **beamed**. Idle word is **beamed** (full report wound without cut; no instruction-shaped tag; single delivery; charCount under cap; runs=1). When the harness tags and cuts at ~2500: **cropped**. When the same tail takes three full runs: **thrice**. When only the tag is present: **tagged**. When SendMessage re-asks re-run the agent: **looped**. When the cut is mid-sentence: **midcut**.

Verdicts: beamed, cropped, thrice, tagged, looped, midcut.

The bench scores one new fact: INSTRUCTION-SHAPED FALSE-POSITIVE → HARD CAP ON A REPORT THAT ARRIVED → COSTLY RE-RUN LOOP. Did the harness cut a delivery that already landed, then sell a full-cost resume that hits the same wall?
