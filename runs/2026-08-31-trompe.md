Title: Desktop app: command-chip renderer matches the command-name tag anywhere in message content, faking a /clear and hiding scrollback (no actual clear). Labels: bug / platform:macos / area:ui / area:desktop. Env: Claude desktop 1.40609.0; Claude Code 2.1.251; macOS 15.7.3 (24G419). Present since desktop 1.14271.0 / CC 2.1.183. Filed by dnorth123.

Facts from the issue only:

- Desktop command-chip renderer decides a message is a command invocation by testing whether its **content contains** the literal command-name tag. Predicate in the shipped bundle: `.includes('<command-name>/clear</command-name>')` (and sibling tags) on `message.content`.
- Any ordinary message that merely quotes that tag as text renders a real `/clear` chip, an "(no output)" line, and a "Context cleared" banner, and collapses the scrollback above it.
- No clear happens: the model retains full context and the session JSONL is complete and untruncated.
- It reads `message.content` only. There is no check for a leading-slash input, a command-message envelope, or an author role, so an **assistant** message containing the tag triggers it just as a user message does.
- Repro: plant a canary (`PATINA-7731-OBSIDIAN` in the issue; this gallery uses `CANARY-TROMPE-88`); send ordinary text quoting the tag mid-message (not leading with a slash); observe chip + (no output) + banner + collapsed scrollback; ask the canary — it answers.
- Session JSONL at `~/.claude/projects/…/*.jsonl`: the tag appears only inside full content messages; record count is continuous with no truncation. No error dialogs. Pure front-end render artifact.
- First found 2026-06-19 on desktop 1.14271.0 / CC 2.1.183. Still present on 1.40609.0 / 2.1.251.
- Suggested fix: gate chip render on a genuine command invocation; fire "Context cleared" + scrollback collapse on an actual clear event, not as a side effect of chip render.

## Why Trompe

Trompe-l'œil is a painted false depth — a gallery wall that looks like a window, a cloth, a cleared desk. The desktop chip renderer is that painting: it paints a `/clear` that never ran. A painted clear is not a hold. Score the pane. Name the class or admit **intact**. Idle word is **intact**. When a quoted tag paints a destructive clear that never ran: **phantom**. When the UI claims context cleared: **cleared**. When prior scrollback is visually hidden: **collapsed**. When `.includes('<command-name>/clear</command-name>')` hits message content: **substring**. When a real `/clear` chip was painted for quoted text: **chip-lied**. When prior turns collapsed out of view: **scrollback-hid**. When the planted canary is still recalled: **canary-kept**. When the tag was quoted as documentation: **quoted-tag**. When "Context cleared" fired with no actual clear: **false-banner**. When this is a front-end render artifact: **render-only**. When session JSONL is continuous: **no-truncate**. When there was no leading-slash / envelope / author-role gate: **envelope-miss**.

Verdicts: intact, phantom, cleared, collapsed, substring, chip-lied, scrollback-hid, canary-kept, quoted-tag, false-banner, render-only, no-truncate, envelope-miss.
