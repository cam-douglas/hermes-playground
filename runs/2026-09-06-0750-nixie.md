Facts from the issue only:

- Claude Desktop for Windows **1.46388.3** (MSIX); Windows 11 Pro 26100; Code tab; ccd_session_mgmt `send_message`.
- Cross-session `send_message` from an `auto` permission-mode sender is silently discarded. The same message from a `bypassPermissions` sender delivers.
- Sender tool result still reports "Message sent/queued"; recipient UI may show the message block optimistically; no user turn is written to the recipient transcript and no model turn runs.
- Delivered send: Mapping line within seconds. Dropped send: no Mapping; after ~45s (sometimes 90s) `peer input … drew no acknowledgement … settled as undelivered`; discarded with no retry.
- Decisive A/B: one hand-opened session, same cwd; auto pings settled-as-undelivered at 45s; flip only permission mode to bypassPermissions and the next ping delivered instantly with a Mapping line. `classifierSummaryEnabled` stayed true.
- 14/14 dropped sends from auto-mode senders; every delivered send from bypassPermissions. 25 settled-as-undelivered events in one main.log across 6 days.
- Ruled out: recipient busy/idle, sender model, chip vs hand-opened, fresh CLI, cwd, recipient identity.
- Workarounds: switch report-back senders to bypassPermissions; verification script greps the settle signature and a transcript fingerprint, then resends on a confirmed drop.
