Title: `Completed turns are repainted, so terminal scrollback loses the recent conversation`. Labels: bug, platform:linux, area:tui. Reporter yiidtw.

Facts from the issue only:

- Scrolling up in a terminal multiplexer does not show the last several exchanges. Older output remains; then a gap where the recent conversation should be.
- The TUI redraws its output region in place. Scrollback only retains what genuinely scrolled off the top. Anything overwritten by a later impression is gone. Recent turns are the part most likely wiped.
- `/resume` renders through the same TUI. `tmux pipe-pane` captures the repaints, not a transcript. Session JSONL under `~/.claude/projects/<slug>/<session-id>.jsonl` is complete and written live, but undiscoverable from “re-read five messages ago,” and the format is not documented as stable.
- In-place repainting buys spinners, live tool status, collapsible output, an editable input line, reflow on resize. A finished turn will never change again, so there is no reason for it to stay in the dynamic region.
- Suggested fix: commit each completed turn as ordinary scrolled lines and repaint only the live region at the bottom. If the UI is Ink-based — the bundled binary contains `measureElement`, `useStdout`, `useInput` — Ink’s `<Static>` writes children once, permanently, above the dynamic area. Treat as a suggestion, not a diagnosis of unseen source.
- Environment: Claude Code 2.1.260 · tmux 3.4 · `TERM=tmux-256color` · Linux 6.8.
