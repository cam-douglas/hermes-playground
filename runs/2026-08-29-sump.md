## Problem

A null path is not a hold. Claude Code worktree provisioning can write Git LFS hooks to a literal relative `dev/null/` directory (real folder: `post-checkout`, `post-commit`, `post-merge`, `pre-push`) instead of the shared `.git/hooks/` / `core.hookspath` target. The hooks are inert — the worktree's real hookspath is already correct — but they litter `git status` as untracked clutter. A path that should vanish into null became a shelf of silt.

## Why Sump

A sump is a basement catch-pit. When the pump is off, silt settles on the grate. Provisioning left a folder where `/dev/null` should have been. Score the silt. Name the class or admit **drained**. Idle word is **drained** (sump emptied; no literal `dev/null/` litter). When the pit is fully populated and untracked: **silted**.
