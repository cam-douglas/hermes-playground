Twice in one day: turn ended while two Bash `run_in_background` tasks still running; completion notifications never delivered; session froze showing a hook statusMessage in the spinner; freezes lasted ~8h and ~1.5h until interrupt/restart, after which pending notifications arrived immediately. Hook scripts used unbounded stdin reads (`dd bs=1048577 count=1` / `payload=$(cat)`). Probe: `time sh hook.sh < <(sleep 6)` blocks exactly 6.003s (pipe open, no EOF); with EOF, 0.052s. ## Problem

An open spile is not a hold. Pipe open, no EOF, for hours. Declared timeout 5s ignored. Session frozen on hook statusMessage. Notifications held until interrupt.

## Why Spile

A cooper's spile is the wooden tap in a barrel. Leave it out and the barrel drains for hours. Reseat it (EOF + enforced timeout) and the wedge stops. Score the tap. Name the class or admit **bunged**. Idle word is **bunged** (spile seated; payload delivered with EOF; declared timeout armed and enforceable). When the #90585 session is already frozen on an open pipe: **wedge**. When the freeze lasted hours: **hours-held**. When settings.json declared 5s and the hook lived longer: **timeout-ignored**. When the pipe is still open with no EOF: **open-pipe**. When the probe blocked exactly as long as the pipe stayed open: **no-eof**. When the hook process was not killed: **script-alive**. When the parent did not enforce timeout while blocked on stdin: **parent-blind**. When statusMessage stuck and notifications queued: **unretracted**. When the script wrapped the read in `timeout 2`: **self-timeout**.

Verdicts: bunged, open-pipe, no-eof, timeout-ignored, wedge, hours-held, script-alive, parent-blind, self-timeout, unretracted.

The station scores one new fact: HOOK STDIN PIPE OPEN (NO EOF) + DECLARED TIMEOUT NOT ENFORCED PARENT-SIDE → SESSION WEDGE FOR HOURS. Did the bung stay seated?
