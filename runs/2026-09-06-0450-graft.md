Facts from the issue only:

- Claude Code 2.1.261, macOS 15 (arm64). Plugin installed from a marketplace entry with `source: { source: "url", url: "…git" }`.
- When a plugin updates, the new cache version directory appears to be seeded from the previous version directory before the fetched content is overlaid.
- Untracked, gitignored, or session-written files are carried into every subsequent version and never collected.
- One August `npm install` replicated into 13 version directories by early September: **1.2 GB for a ~100 MB plugin**.
- Stray `node_modules` mtimes chain to the previous version dir mtime. Nine of thirteen listed rows chain exactly. Four unlisted hashes not invented.
- Copies are real, not hardlinks — distinct inodes, `st_nlink = 1` on both sides of a sampled pair.
- Plugin remote is clean: `node_modules` gitignored, untracked, absent from default branch (contents API). Plugin declares no hooks and no install scripts.
- Anything written once (scratch, logs, credentials) becomes permanent self-replicating accumulation. The cache stops being a cache.
- Expected: new version directory contains the plugin's fetched content and nothing else. Either populate from a clean fetch, or carry forward only paths the plugin declares.
