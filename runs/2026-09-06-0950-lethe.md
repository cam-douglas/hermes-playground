Facts from the issue only:

- Claude in Chrome **1.0.91** (`fcoeoabgfenejglbffodgkkbkcdhcgfn`); Chrome **152.0.7977.82** Flatpak; Fedora Linux 44; Wayland (niri compositor).
- After anything that ends the Chrome browser session (reboot, full Chrome quit), the side panel shows **Sign in** while `claude.ai` in a normal tab stays fully logged in. Unrelated sites keep their sessions.
- Extension still knows the account: `accountUuid` and `tokenOrg` intact on `chrome.storage.local`. This is NOT a sign-out.
- Auth tokens (`accessToken`, `refreshToken`, `tokenExpiry`) are routed to `chrome.storage.session` (RAM-only) by design. They evaporate when the browser session ends. Refresh-token path cannot run after session end.
- Bundle ships silent re-auth (`cic_ext_silent_reauth` / `Bs()`) with `chrome.identity.launchWebAuthFlow({interactive:false})` after a `claude.ai/api/bootstrap` probe — designed for exactly this case — but the session is not restored.
- `lastAuthFailureReason` never written → not account_mismatch/consent_required terminal path; full sign-out routine did not run either.
- Leaves `disabled_by_gate` / `authorize_failed` / path never reached. Tight timeouts (8s bootstrap, 5s non-interactive flow) may contribute on slow links but do not explain warm-network cases.
- Workaround: none automatic; clicking Sign in completes without re-entering credentials because the claude.ai session is alive — but it is a manual step after every browser session.
- Profile switch reproduces the same Sign-in screen without a reboot (user-visible observation; `chrome.storage.session` not instrumented across that transition).
