## Problem

A written schedule is not a hold. The writer and the loader disagree on `fireAt` type. The MCP documents and writes ISO-8601 strings. The disk loader Zod-expects a number (epoch ms). One mismatch rejects the entire registry. Every routine goes dark. Every liveness proxy stays green. There is no in-app signal that “no routine has fired for N hours while the dispatcher believes itself healthy.”

## Why Cotter

A cotter is the split pin that holds an axle. Score the tray. Name the class or admit **snug**. Idle word is **snug** (every fireAt is epoch ms; Zod loads the tray; dispatches match; MCP tools present). When one ISO string fail-closes the registry: **poison**. When an update empties `scheduledTasks: []`: **wipe**. When lastFired advances with zero work: **hollow**. When the recurring pin vanishes: **vanish**. When scheduled-task MCP tools are absent: **mute-mcp**.

Verdicts: snug, poison, wipe, hollow, vanish, mute-mcp.

The bench scores one new fact: POISON-PILL REGISTRY SCHEMA. Did one wrong-typed pin kill the whole set while the green gages lied?
