Title: `change_directory leaves $CLAUDE_PROJECT_DIR at the launch project, and the resulting ENOENT silently erases every user prompt (exit 2 reads as deny)`. Labels: bug / has-repro / platform:macos / area:hooks / data-loss. Reporter Rasherb69 (Lewis Bacon).

Facts from the issue only:

- `change_directory` loads new project hooks/settings but does not repoint `$CLAUDE_PROJECT_DIR` (stays at the launch dir, often a scratch workspace).
- Newly-adopted UserPromptSubmit hooks resolve under the old path → ENOENT.
- python3 exits 2 on a missing script; argparse also exits 2; UserPromptSubmit treats exit 2 as deny and erases the prompt.
- The prompt never reaches the model; four consecutive prompts were erased in 33 seconds in the wild.
- Asking what is wrong is itself a prompt, so the question is destroyed; only recoverable via session JSONL.
- SessionStart hooks do not fire on mid-session `change_directory` (partial init).
- Suggested fixes: repoint `CLAUDE_PROJECT_DIR`; distinguish cannot-run vs deny; never erase silently.
- Shell-form workaround with a fallback path; exec-form cannot express fallback (related #81291).
- Environment: Claude Code 2.1.204; failing session in Claude desktop app; macOS 26.5.2 arm64; Node v24.15.0; python3 3.14.5; shell-form hooks.
- Hypothesis (non-binding): change_directory loads the new project's hooks and settings but leaves `$CLAUDE_PROJECT_DIR` pinned at the launch directory; UserPromptSubmit then ENOENTs, exits 2, and is read as deny — so the standing line is dumped into the hellbox instead of staying set in the form.
