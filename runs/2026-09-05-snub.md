Facts from the issue only:

- Claude Code 2.1.260 (Claude Desktop, Code tab); macOS 26.5.2 arm64.
- `/opt/homebrew/bin/bash` GNU bash **5.3.15** (also 5.3.9 in prior reports) **affected**; `/bin/bash` GNU bash **3.2.57** **not** affected.
- Trigger: macOS with bash 5.1+ first on PATH (default after `brew install bash`).
- Writing a file whose contents are **513–65535 bytes** via Bash heredoc → hang for full **120s timeout** and target file left **truncated to 0 bytes**.
- Two Claude Code behaviours turn an upstream bash bug into data loss: (1) Bash tool uses PATH-resolved bash (picks Homebrew); (2) redirect truncates the target **before** the heredoc body is known to have arrived.
- Auto mode / bypass-permissions steer model to prefer `cat <<EOF` over Write tool (#92178, #88041, #90599, #88791) — maximises exposure.
- Upstream: bash 5.1 changed heredocs from temp files to pipes; temp-file fallback only at ≥65536 bytes (Linux PIPE_BUF assumption). macOS pipe capacity **512 bytes** (`getconf PIPE_BUF /` → 512). Writer fills pipe and blocks before forking the drain child → deadlock.
- Bisect via Bash tool: 377B OK, 496B OK, ~600B HANGS, ~960B/2KB/4KB/5KB HANGS; 100KB OK (temp-file path). Only total body size matters.
- Reporter emptied a ~2KB mix.exs; COMPLETED never printed after heredoc.
- Requested fixes (product can score against these as checklist, not implement them): don't destroy target on failed write; invoke `/bin/bash` explicitly; fail fast with diagnostic; reconsider auto-mode heredoc guidance; workaround `shopt -s compat44` restores pre-5.1 temp-file heredocs (undocumented side effect).
