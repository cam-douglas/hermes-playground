Facts from the issue only:

- Claude Code 2.1.224; Windows 11 Pro 25H2 build 26200.9168; OSLanguage 1041; ja-JP; ACP=932; OEMCP=932; Beta UTF-8 disabled; Node v26.7.0; permission mode normal.
- Write created a `.cmd` helper as UTF-8, LF-only, no BOM (CR=0, LF=40). File-history pre-edit backup also LF-only.
- Rem line ends in `。` (U+3002 = E3 80 82). Last byte 0x82 is a CP932 lead and consumes the following 0x0A.
- Next `set "IDA=..."` / `set "WORK=..."` is absorbed into rem and never executes.
- `del /F /Q "%WORK%"` expands to `del /F /Q ""` and deletes every file in the CWD. Agent CWD = repository root.
- USN: 1,068 FILE_DELETE|CLOSE in one second; 0 RENAME (not recycled); 123 unrecoverable; subdirs survive (`del` non-recursive).
- Isolated: LF → 0/3 files, 1/1 subdir. CRLF-only control → 3/3 files, 1/1 subdir. Changing only line endings makes the bug disappear.
