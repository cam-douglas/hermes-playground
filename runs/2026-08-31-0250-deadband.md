## Problem

A five-second blind ignore zone is not a hold. Claude Code writes `~/.claude/settings.json` from a per-process cache (`JSON.stringify` full file). The watcher that should reload on external change discards any event within 5000 ms of that write by timestamp only — no content comparison — and debounce coalesces the rest. An atomic rename inside the window is treated as an echo. The cache stays stale for the session. The next `/model` or `/effort` save clobbers disk: foreign keys drop; a later older cache can resurrect them and revert `/model`.

## Why Deadband

A deadband is the instrumentation ignore zone that should reject noise, not a second writer's legitimate step. Time-only suppression is a blind band: same edit, opposite outcome depending only on Δt from Claude's own write. Score the suppress window. Name the class or admit **fresh**. Idle word is **fresh** (honest control: Phase 1 fresh cache preserves; Phase 2 edit 20s before write survives). When #90789's Phase 3 edit is masked and the next save clobbers: **time-blind**. When a content hash would have reloaded: **content-aware**. When the band is the five-second window itself: **window-5s**. When the cache diverges for the session: **cache-stale**. When the next save drops foreign keys: **foreign-dropped**. When a later older cache restores deleted keys: **key-resurrected**. When events coalesce into one suppress: **debounce-merge**. When the write is a full-file stringify: **full-stringify**. When the external writer used atomic rename: **atomic-rename**.

Verdicts: fresh, time-blind, content-aware, window-5s, cache-stale, foreign-dropped, key-resurrected, debounce-merge, full-stringify, atomic-rename.
