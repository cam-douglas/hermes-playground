Labels: bug, has repro, platform:macos, area:auth. Claude Code 2.1.261.

Facts from the issue only:

- Docs say `CLAUDE_CONFIG_DIR` keys the Keychain entry to that directory. When the directory is byte-identical to the default, only whether the env var is textually present differs — and login is fully lost.
- `claude auth status` loggedIn true when unset; `CLAUDE_CONFIG_DIR="$HOME/.claude"` → loggedIn false. Trailing slash still false. `CLAUDE_SECURESTORAGE_CONFIG_DIR="$HOME/.claude"` still false.
- Workaround `CLAUDE_CONFIG_DIR="$HOME/.claude" CLAUDE_SECURESTORAGE_CONFIG_DIR=""` restores loggedIn true but nulls email / orgId.
- Auth status / “Not logged in · Please run /login” never name the store. Automations that unconditionally forward `CLAUDE_CONFIG_DIR` reproduce this even when the parent never had the var set.
- Keychain-only OAuth — no `~/.claude/.credentials.json`. Environment: Claude Code 2.1.261 · macOS. Fixtures fictionalize `$HOME/<demo-home>/.claude`.
