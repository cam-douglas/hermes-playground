Facts from the issue only:

- Claude Code 2.1.260 (verified 2.1.247 / 2.1.258 / 2.1.259 / 2.1.260). Last working 2.1.246. Regression since 2.1.247.
- WezTerm 20240203-110809-5046fc22 on Windows 11 hosting WSL2 Ubuntu. Native Linux x64 Claude Code inside WSL2. TERM=xterm-256color, TERM_PROGRAM=WezTerm.
- 2.1.246 sent `ESC[>1u`. 2.1.247+ sends `ESC[>5u` (includes Kitty flag 4 = report alternate keys).
- WezTerm encodes Shift+1 as `ESC[49:33;2u` (unshifted 1, shifted !). Parser reads first sub-param + modifier, never the second (shifted) field; reconstructs by uppercasing unshifted → wrong for symbols.
- Insert table from the issue (pty, 2.1.260):

  | input | expected | actual |
  |-------|----------|--------|
  | `ESC[97:65;2u` | A | A |
  | `ESC[49:33;2u` | ! | 1 |
  | `ESC[59:58;2u` | : | ; |
  | `ESC[47:63;2u` | ? | / |
  | `ESC[97:65;2:1u` | A | (dropped) |
  | `ESC[97;2:1u` | A | (dropped) |
  | `ESC[97:65;130u` | A | A |
  | `ESC[9;2u` | mode cycles | ok |
  | `ESC[13;2u` | newline | ok |

- On WezTerm→ConPTY→WSL, colon-bearing sequences often insert nothing (Shift+A / Shift+1 / Shift+?). Shift+Tab / Shift+Enter still work (no colon sub-parameter).
- Quote: "Claude Code's CSI u parser reads the first sub-parameter (unshifted key) and the third (base layout, used for Ctrl) but never the second (shifted key)" / "requesting flag 4 without consuming the field it adds."
- Secondary: CSI-u with event-type sub-field `ESC[97:65;2:1u` dropped by a regex that only accepts a bare modifier number.
- Workaround noted in the issue: `enable_kitty_keyboard = false`, or launch with TERM_PROGRAM set to anything other than WezTerm.
