Facts from the issue only:

- Calling `mcp__visualize__show_widget` (visualize MCP app): a first call that fails input validation, followed by a retry with the same `title`, leaves TWO duplicate widget cards in the chat UI.
- The failed call is not supposed to render anything, but it does, and that rendered content persists after the retry succeeds (does not disappear).
- Schema/backend mismatch: declared JSON schema lists `required: ["loading_messages"]` only (`title` optional per schema), but backend enforces `title` and throws MCP error `-32602` when missing.
- Repro: (1) call show_widget with widget_code + loading_messages, omit title → `-32602` invalid_type path title; (2) retry with title included → succeeds; (3) UI shows two "Widget from visualize show_widget" cards.
- Expected: schema should mark title required OR backend accept missing title; validation failure must never render UI; retry with same title must not accumulate a second card.
