Facts from the issue only:

- Desktop Code tab stops rendering conversation history ~3 days in the past while the transcript on disk contains everything up to the present. Two app updates (2026-09-03 and 2026-09-04) did not fix it.
- This is NOT data loss. Session `698952e6…`: 10,381 entries on 09-02, 7,130 on 09-03, 705 on 09-04. 27,594 recent entries present and not displayed.
- Parent chain is intact — walking `parentUuid` backwards from the newest entry terminates at `parentUuid: null`. No dangling reference, no corruption.
- The transcript is a forest. `/compact` and session resumes create multiple roots and thousands of leaves in one file.
- Affected session `698952e6…`: 60,050 entries / 5 roots / 2,110 leaves; newest-message branch 9,340 · 09-02 → 09-04; largest branch 13,914 · 08-21 → 09-02; largest == newest? NO.
- Control session `76af434c…`: 9,841 entries / 1 root / 332 leaves; newest and largest both 5,045 · 09-03 → 09-04; renders fine.
- In the affected session the largest branch ends on 09-02 — exactly where the UI stops rendering.
- Hypothesis (non-binding): the client selects the branch to render by size, or by an arbitrary/older leaf, instead of by the most recent leaf. When `/compact` or a resume forks the transcript, the pre-fork branch can remain larger than the post-fork one.
- Expected: render the branch containing the most recent message; if multiple branches are retained, indicate that other branches exist.
