## Problem

A scheduled-task run completes. The transcript ends. `list_sessions` says `isRunning: false`. The UI marks the session idle. The headless worker — `claude` on macOS, often with a `disclaimer` parent; `claude.exe --resume … --output-format stream-json` on Windows — stays resident. Cron fires again. The stack grows until load, RSS, or commit charge takes the machine down. Nothing in the UI surfaces it, because each session correctly reports success.

## Why Limpet

A limpet clamps a wet rock and does not let go when the tide drops. The session already finished — the tide went out — and the worker is still glued to the basalt. Score the pool. Name the class or admit **shed**. Idle word is **shed**. When end_turn / session done meets a resident process: **clamped**. When the parent pair is still alive: **paired** / **macos-pair**. When cron stacked them: **stacked**. When RSS grew: **bloated**. When the UI is idle after the end: **idle-after-end**. When stop_reason is end_turn: **end-turn-held**. When `--resume` never exits: **resume-stuck** / **windows-resume**. When MCP children survive: **mcp-child**. When a reaper already pried them: **reaped**.

Verdicts: shed, clamped, paired, stacked, bloated, idle-after-end, end-turn-held, resume-stuck, mcp-child, reaped, windows-resume, macos-pair.
