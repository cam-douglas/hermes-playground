Title: [BUG] Windows: Claude Code CLI corrupts stdio MCP password arguments when launching npx through cmd.exe. Labels: bug / has-repro / platform:windows / area:mcp. Reporter Maomaoxion.

Facts from the issue only:

- On native Windows (not WSL), MCP config with `command: "npx"` is launched through `cmd.exe /d /s /c`.
- Args containing cmd metacharacters (`^ & | < > %`) are reparsed before they reach the MCP server. Passwords, tokens, and connection strings break.
- FAKE demo password from the issue: `P@ss^&w0rd`. Same value works via Codex CLI and via `command: "node"` with an absolute path.
- Observed child cmdline: `cmd.exe /d /s /c "npx ^"universal-db-mcp^" ... ^"--password^" ^"P@ss^^&w0rd^" ..."`.
- Extra caret escaping can sometimes compensate for one parse layer but is inconsistent across parse layers.
- Codex CLI does not add this `cmd.exe` wrapper for the same MCP use case.
- Workaround: bypass `npx` and launch the JavaScript entry with `node.exe` and an absolute path to `universal-db-mcp/dist/index.js`.
- MCP server `universal-db-mcp`; transport stdio; Windows 11; Node 20.x and 22.x; PowerShell / Windows Terminal.
