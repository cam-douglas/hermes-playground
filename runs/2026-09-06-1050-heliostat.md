Facts from the issue only:

- `"theme": "auto"` resolves once at startup and never follows a live light/dark switch on Windows Terminal until Claude Code is restarted (or `/theme`).
- Detection itself works. The trigger is missing: resample is gated solely on DECSET 2031 (`CSI ? 2031 h`), parsing `CSI ? 997 ; [12] n` off stdin, then re-querying OSC 11.
- Windows Terminal does not implement mode 2031 (microsoft/terminal#20335 closed 2026-07-31, "somewhat under-specified"). On WT 1.24.11911.0 + Claude Code 2.1.261: `DECRQM ? 2031` → `0` NOT RECOGNIZED; controls `?2026` and `?2004` ARE supported (so the `0` is real).
- OSC 11 BEFORE flip (light): `rgb:fafa/fafa/fafa`; AFTER flip (dark): `rgb:2828/2c2c/3434`. WT reports the new background immediately; Claude Code never asks again.
- With `?2031` enabled and OS theme flipped for 45s across several flips: nothing arrives on stdin.
- Injecting `ESC [ ? 997 ; 2 n` into the console input buffer makes Claude Code immediately re-query OSC 11 and switch theme in a live session; `;1n` switches back. OSC 11 path, parser, and repaint all work — never invoked on this terminal.
- Repro: Win11 + WT with `{dark,light}` colorScheme pair; theme auto; start light; switch OS to dark → terminal repaints, Claude Code stays light until restart/`/theme`.
- Request: when `DECRQM ?2031` is unrecognized, fall back to OSC 11 re-query on focus regain and/or interval. Binary already has a focus-driven re-query path gated behind `CLAUDE_BG_BACKEND === "daemon"` rather than behind 2031 support.
- Environment: win32 Win11 Enterprise 26200, WT 1.24.11911.0, Claude Code 2.1.261, settings theme auto.
