Reporter iamsteamboat.

Facts from the issue only:

- Enabling the in-app "launch at startup" option writes `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Claude` to `"C:\Program Files\WindowsApps\Claude_1.24012.11.0_x64__pzs8sxrjxfjjc\app\claude.exe"`.
- MSIX installs into a version-named folder. The next auto-update (1.25927.0.0 on 2026-08-04) removed that folder, and none of the nine updates since has rewritten the entry.
- At every logon Windows tries to launch a path that does not exist and fails silently.
- The entry was never registered under `Explorer\StartupApproved\Run`, so Settings → Apps → Startup does not show it as failing either.
- Observed on 1.24012.11.0. Reporter did not re-enable the toggle after it broke; the stale entry is still present, which at minimum shows that updates do not clean up or refresh an existing entry.
- Package manifest declares `windows.startupTask` (`ClaudeStartup`, Executable=`app\Claude.exe`). Registration shows State = 0 (Disabled) and UserEnabledStartupOnce = 0.
- On 1.24012.11.0 the in-app toggle did not enable the mechanism that survives updates, and Claude showed as Off in Settings → Apps → Startup even though it was turned on in the app.
- Expected: toggle should call the Windows.ApplicationModel.StartupTask API (`ClaudeStartup`) instead of writing a versioned exe path to HKCU\Run, or at minimum rewrite the Run entry with the current path on every launch/update.
- Environment: Claude Desktop 1.46388.1.0 MSIX `Claude_pzs8sxrjxfjjc`; Windows 11 Home 10.0.26200; toggle enabled 2026-08-03/04 on 1.24012.11.0; package history 1.24012.9.0 → 1.24012.11.0 → 1.25927.0.0 → … → 1.46388.1.0.
- Hypothesis (non-binding): toggle wrote a versioned HKCU\Run instead of enabling the StartupTask API; updates do not refresh Run; silent fail.
