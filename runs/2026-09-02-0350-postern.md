Facts from the issue only:

- v2.1.248 closed the *symptom* of #89401 by falling back to `/tmp/cc-socks-<uid>`. Two problems remain.
- Problem 1 FIRST-COME: `/tmp/cc-socks` is still the shared primary. `/tmp` is world-writable sticky. First account after each `/tmp` clear creates `/tmp/cc-socks` at mode 0700 and keeps it. Every other account fails the owner check and takes the per-uid path. macOS clears `/tmp`, so the winner can change after a reboot. Peer discovery does not break: each session writes absolute `messagingSocketPath` into `~/.claude/sessions/<pid>.json`. Cost is diagnostic. The uid suffix costs 4 bytes of a 103-byte UDS path budget. Reporter asks to make `cc-socks-<uid>` the default.
- Problem 2 SQUAT BOTH NAMES: any unprivileged local account can take both names. The refusal path tries the per-uid directory once, then stops. `nNn()` builds the fallback from a fixed uid so the target name is public and predictable. Fallback ignores both `XDG_RUNTIME_DIR` and `CLAUDE_CODE_TMPDIR`. If both dirs are pre-created 0700 by another account, both owner checks fail and cross-session messaging turns off.
- Scope: denial of service only. Owner check + `peerToken` file still stop the squatting account from receiving anyone else's messages. Attacker needs a local login. Realistic targets: shared Macs, build hosts, CI runners with several service accounts.
- Suggested fix: try a third location under the user's own home; report the refusal in `/status`.
- Workaround: `XDG_RUNTIME_DIR=/tmp/claude-<uid>` (Claude already creates `/tmp/claude-<uid>` at 0700). Resulting socket path 35 bytes. Version 2.1.251 stopped project-level `.claude/settings.json` from setting CLAUDE_CODE_TMPDIR/TMPDIR/TMP/TEMP. Fallback `nNn()` still ignores those vars.
