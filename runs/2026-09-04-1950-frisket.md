Title: `PreToolUse hook on Write/Edit/MultiEdit/NotebookEdit is not enforced (PostToolUse on same matcher fires reliably)`. Labels: bug / has repro / platform:macos / area:hooks. Reporter technoashu.

Facts from the issue only:

- CLI 2.1.245 on macOS Darwin 25.3.0. Also reproduced on earlier builds over ~2 weeks.
- Sync PreToolUse hook in `.claude/settings.json` for matcher `Write|Edit|MultiEdit|NotebookEdit` is not enforced.
- Hook returns `{"permissionDecision":"deny",...}` but the write still completes.
- PostToolUse on the identical matcher fires reliably every time.
- Canary instrumentation: for a real Write, canary captured `result=DENY:...` — deny computed — and the write still completed.
- `--debug hooks`: `PostToolUse:Write` registers and fires (`Hooks: Registering async hook ... (PostToolUse:Write)`). PreToolUse never appears — no registration, no invocation.
- SessionStart / SessionEnd hooks log clean success lines, so hook execution in general is visible; PreToolUse specifically is the omission.
- Reproduced under both `--permission-mode bypassPermissions` and normal permission mode with `--allowedTools`.
- Impact: any project relying on PreToolUse to enforce a Write-family invariant currently gets zero real enforcement, silently.

Commenter [yurukusa](https://github.com/anthropics/claude-code/issues/91574#issuecomment-5531871213) on Linux 6.6.87.2 (WSL2, Ubuntu 24.04), Claude Code 2.1.258, could NOT reproduce:

- `repro.txt` not created.

- PostToolUse canary: no line — consistent with the call being blocked.
- Deny held even under `bypassPermissions`.
- Two variables differ and were not separated: OS (macOS 25.3.0 vs Linux/WSL2) and version (2.1.245 vs 2.1.258). If still on 2.1.258 then macOS-specific.
