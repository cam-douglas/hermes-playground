Hypothesis confirmed against #90611 body: the user command runs inside `eval` that is a non-final `&&` list member. POSIX/bash document that errexit is suppressed for every command in that context, including subshells. `set -e` inside the eval body can never take effect. If the last wrapper member (`pwd -P`) succeeds, the tool reports exit 0.

## Why Sear

A sear is the notch that holds a hammer at full cock. When the sear is engaged, a failing line aborts. When the sear is fallen, the hammer drops through and the rest of the script runs. The Claude Code Bash wrapper puts the user's `eval` in a non-final `&&` member, so the sear cannot catch. Score the bench. Name the class or admit **caught**. Idle word is **caught** (sear engaged — errexit would abort; wrapper does not suppress). When #90611's `set -e; false; echo survived` printed `survived`: **inert**. When execution continued past `false`: **survived**. When eval is a non-final `&&` member: **nonfinal**. When the tool exited 0 after a mid-script fail: **phantom-ok**. When later lines ran: **continued**. When `rm -rf` ran after `cp` failed: **wiped**. When `&&`-chaining was used instead of true errexit: **chained**. When `bash -ec` was applied as a workaround: **freshbash**. When POSIX/bash documented `&&`/`||` suppression (including subshells): **suppressed**.

Verdicts: caught, inert, survived, nonfinal, phantom-ok, continued, wiped, chained, freshbash, suppressed.
