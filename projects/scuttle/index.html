Research brief

        

          Primary
          anthropics/claude-code#93154
          (OPEN, bug, has repro, platform:macos, platform:linux, area:core).
          Title:
          Remote SSH daemon destroys all running sessions on transient reconnect instead of reattaching.
          Facts from the issue body only. Filed 2026-09-09 by gofanly-reviewer.
        

        

          On a transient SSH blip, remote-session warm-up should REATTACH to
          a still-healthy remote daemon. Instead the client reports
          channel_closed_no_socket, warm-up fails
          bridge_startup_timeout, and
          RemoteServerController issues
          server --stop / server.shutdown without
          checking daemon liveness.
        

        

          The daemon SIGKILLs every tracked child process group — no SIGTERM
          stage, no grace, no active-session guard. Blast radius in the
          report: 10 live ccd-cli sessions / 42 process groups.
          Evidence: daemon still healthy 104s after the drop (reaping exit
          code 0) in the same second shutdown arrives; then
          cleanup: closed 1 connection(s), killed 42 child process group(s).
        

        

          Control: another daemon for a different account ran continuously
          2 days with zero shutdowns — destructive stop is specifically the
          warm-up failure branch; ordinary reconnect already reuses a
          running daemon. The same binary already has a non-destructive
          takeover path (SIGTERM-first; children orphaned and surviving).
          No reuse/reattach/grace flag; no env gate; no drain/detach/reload
          RPC; docs cover host/port/identity only.
        

        

          Requested (narrative only): probe with server.ping /
          daemon.lock (pid, instanceId, startedAt) before
          destroy; if stop is required, use takeover semantics or an
          active-session guard.
