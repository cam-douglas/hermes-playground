Research brief

The desktop app re-sends initialize (and get_workspace_diff) to a Remote Control session every 60 seconds while that session is on screen. Every minute the CLI receives a burst of control_request subtype=initialize (2–3 of them) followed by one get_workspace_diff. The CLI answers each initialize with a control_response and emits a fresh system/init and system/status into the session event log. That is ~14 events per minute, ~800+ events per hour, with nothing typed.

The transcript loader only looks at the newest 2,000 events and gives up. When a session is opened it fetches four pages of 500, then stops. If those 2,000 are all control/system noise, the view shows No messages yet plus a Load earlier messages button; each click loads 500 more. For one published session the conversation only appears after 8 clicks. Browser tabs do not poll; only desktop. Regression: desktop 1.44121.4 ≤20 init/hr; 1.46388.1 → 120/hr; 1.52386.6 → 180/hr.
