          Title:
          [BUG] Orphaned worktree entry is retried every 30 minutes forever; cleanup can never succeed.
          Facts from the issue body only. Claude desktop for Windows 1.49585.0.0
          (first observed 1.34493.1.0; 13 updates). Claude Code 2.1.216.
          Author emanon-i. Filed 2026-09-09T12:45:23Z.
        

        

          A worktree directory in a partially-removed state — .git
          link file gone, directory still exists — puts desktop
          WorktreePool GC into a permanent retry loop. Same
          five-line sequence every 30 minutes. Reporter saw 853 repeats over
          20 days across restarts and 13 app updates. Worktree
          clever-bassi-12c5dc, leased by none.
        

        

          Deadlock: (1) git worktree remove --force fails with
          fatal: is not a working tree because the
          .git link is gone; (2) manual-cleanup fallback refuses
          with .git link missing (partial remove); not safe to rm
          — same reason. Store entry is not pruned despite
          [WorktreePool] Pruning orphaned store entry … (directory gone or not a worktree).
        

        

          Expected (narrative only): fallback treats partial-remove as
          expected and removes after git worktree prune, or
          prune/mark permanently-failed after the first failure so GC stops;
          surface once to the user instead of infinite retries.
