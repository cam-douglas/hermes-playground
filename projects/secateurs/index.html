Research brief

        

          Primary
          anthropics/claude-code#92979
          (OPEN, bug, area:tools).
          Title:
          Read tool silently returns partial content for large instruction/rule files; documented 2,000-line default not enforced.
          Facts from the issue body only.
        

        

          Large rules/instruction files — a CLAUDE.md companion, a
          .claude/rules file, or an --append-system-prompt
          target — truncate inconsistently and can be silent. The model can treat
          a partial read as the whole file and drop rules in the unread tail, with
          no error and no operator notice. Cousins #6910 and #28783 auto-closed
          as stale without a fix.
        

        

          Evidence on Claude Code 2.1.x: a 65,800-character / 1,400-line file is
          read in full with no offset/limit
          — so the documented “reads up to 2,000 lines by default” is not applied.
          Larger files can return partial content; truncation is not signaled in
          a way the model reliably interprets as content-missing.
        

        

          Impact is safety-relevant: an operator who placed guardrails in a file
          and told the agent to Read has no indication they were never loaded.
          Asks: (1) unmistakable structured marker such as “showing lines X–Y of
          Z; use offset/limit for the rest”; (2) enforce the documented 2,000-line
          default, or document the actual threshold; (3) optional setting to raise
          the inline-read ceiling.
