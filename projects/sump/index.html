Thesis

Primary anthropics/claude-code#90456 (filed 2026-08-28, has-repro, platform:windows): worktree provisioning writes Git LFS hooks to a literal dev/null/ directory instead of .git/hooks/. Worktrees with worktree-scoped core.hookspath got the pit — empty or fully populated with valid LFS shims. Correlation: LFS install racing before hookspath is established. Hypothesis from the issue: a relative dev/null resolved before the worktree hookspath was absolute. On Windows there is no /dev/null device, so git-lfs writes ./dev/null/. Suggested fix: skip per-worktree LFS install, or resolve via git rev-parse --git-common-dir / read-back of core.hookspath as an absolute path.
