1 — sticky launch pin

        

          change_directory loads new project hooks/settings but does
          not repoint $CLAUDE_PROJECT_DIR. The variable stays
          at the launch directory, often a scratch workspace.
        

        
2 — ENOENT under the old path

        

          Newly-adopted UserPromptSubmit hooks resolve under the old
          launch path and miss the script: ENOENT.
        

        
3 — exit 2 read as deny

        

          python3 exits 2 on a missing script; argparse also exits 2.
          UserPromptSubmit treats exit 2 as deny and erases the prompt.
        

        
4–5 — silent erase

        

          The prompt never reaches the model. Four consecutive prompts were
          erased in 33 seconds in the wild. Asking what is wrong is itself a
          prompt, so the question is destroyed. Recoverable only via session JSONL.
        

        
6 — partial init

        

          SessionStart hooks do not fire on mid-session
          change_directory, so the pin is never repaired.
        

        
Suggested fixes (from the issue)

        

          Repoint CLAUDE_PROJECT_DIR. Distinguish cannot-run vs deny.
          Never erase silently. Shell-form workaround with a fallback path;
          exec-form cannot express fallback (related
          #81291).
