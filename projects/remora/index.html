Research brief

Primary anthropics/claude-code#92934 (OPEN, bug, has repro, platform:windows, area:hooks). Title: Windows: synchronous PostToolUse delays tool results until a persistent child exits. Facts from the issue body only.

On Windows, a synchronous PostToolUse command hook can delay the tool result until a persistent descendant exits, even though the configured hook process has already exited successfully. This is separate from #90049: it does not require EnterWorktree and produces a bounded wait rather than the worktree-transition result-loss symptom.

Repro from the issue: child.ps1 sleeps 90 seconds. hook.ps1 reads stdin, starts that child with stdin/stdout/stderr redirected to files, then exits 0. settings.json PostToolUse matcher PowerShell runs the hook with timeout 120. Running Get-Date -Format o: the main tool completes (~925ms), hook.ps1 exits immediately, but Claude Code delays the tool result until child.ps1 exits (~90s). async:true on the hook avoids the blocking path in the control. One controlled reproduction; it does not establish the internal mechanism. Diagnostic assay only — no live Claude, no secrets, no network to Anthropic.
