          Primary OPEN issue:
          anthropics/claude-code#92294.

          Labels: bug, has repro, platform:macos, area:mcp, area:ui.

1 — The schema and the backend disagree

        

          Declared JSON schema lists required: ["loading_messages"] only
          (title optional per schema). Backend enforces title
          and throws MCP error -32602 when missing. That mismatch
          produces the first failed call in practice.
        

        
2 — A failed pull still printed

        

          Call mcp__visualize__show_widget with widget_code +
          loading_messages, omit title → -32602 invalid_type path title.
          The failed call is not supposed to render anything. It does.
        

        
3 — Same-title retry doubled the sheet

        

          Retry with title included succeeds. The UI shows two
          “Widget from visualize show_widget” cards. The ghost from the failed
          call persists alongside the success card.
        

        
4 — Why this is not a clean proof

        

          Not #53030: that widget renders then disappears on HTTP 400
          (transient, self-corrects). Here the failed-call duplicate
          persists. Live-reproduced 2026-09-05 on Claude Code desktop
          (Code tab), macOS, Claude Code 2.1.220.
        

        
Expected (from the issue — checklist, not implemented here)

        

          Schema should mark title required OR backend accept missing title;
          validation failure must never render UI; retry with same title must
          not accumulate a second card.
        

        
Likely path (NON-BINDING)

        

          The desk should make “validation-failed show_widget still prints,
          then same-title retry doubles the sheet” visceral. Discard if
          evidence disagrees. Do not claim unseen source.
