1 — Trust is not the seat

        

          Opening claude://code/new?folder=<abs>&q=<text> shows
          “Trust this workspace?” for the right folder. After Trust the composer
          chip and the prompt are correct. Enter still mints a scratch.
        

        
2 — Trigger is string equality

        

          The folder in the link is the same string as the folder already
          selected in the composer. When the selected folder differs, the same
          link seats the path: saveTrust → checkGhAvailable →
          session in the folder.
        

        
3 — Scratch mint after saveTrust

        

          %LOCALAPPDATA%\Claude\Logs\main.log:
          checkTrust → saveTrust →
          LocalSessions.createScratchWorkspace →
          scratch-2026-09-04-43ac21 under
          %APPDATA%\Claude\scratch-workspaces. Listed as
          No folder. Prompt text arrives intact.
        

        
4 — Slash and case are not a workaround

        

          C:/Users/… or a lowercase drive makes the link work, which
          points to a plain string compare in the renderer. Those spellings then
          show up as separate sidebar groups.
        

        
Expected (from the issue)

        

          Session starts in the trusted folder. Same-folder reopen is the
          common case for an internal launcher that always sends the current
          matter path.
        

        
Likely path (NON-BINDING)

        

          Renderer compares folder strings with === (or equivalent)
          and, on equality, takes the “already have this folder” branch that
          mints a scratch instead of seating the trusted cwd. Discard if issue
