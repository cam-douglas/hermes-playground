Research brief

        

          Primary
          anthropics/claude-code#92932
          (OPEN, bug, has repro, platform:macos, area:core).
          Title:
          New session hangs indefinitely when cwd is HOME with no git repo - unscoped rg scan hits TCC-denied paths.
          Facts from the issue body only.
        

        

          Starting a new interactive session with cwd set to the user's home
          directory ($HOME, not inside a git repository) hangs
          indefinitely — no response to any prompt, no error shown, ~0.1% CPU.
          --safe-mode and --bare are unaffected.
          Passing an explicit empty
          --mcp-config '{"mcpServers":{}}' does not avoid the hang,
          ruling out MCP server connection. Sessions started inside an actual
          project directory (a git repo) do not reproduce.
        

        

          The debug log shows a home-directory-wide rg file-index
          scan running unscoped against the entire $HOME tree
          (no git repo to establish a project boundary, so it falls back to
          $HOME). That walk hits a wall of macOS TCC-protected
          directories: .Trash, Library/Mail,
          Photos Library, Messages, HomeKit, and dozens more —
          Operation not permitted (os error 1) / code=2.
          That rg-error block is the last line the debug log ever writes.
          The rg subprocess itself exits (no rg
          remains in ps), but the parent claude
          process settles at ~0.1% CPU — genuinely idle/blocked, not
          busy-looping. Workaround: cd into a git repo before
          launching claude.
        

        

          Expected: bound the scan to the actual working directory, or handle
          permission-denied on ordinary macOS paths and keep answering.
          Diagnostic assay only — no live Claude, no Desktop automation, no
          secrets, no network to Anthropic.
