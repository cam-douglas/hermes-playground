Research brief

        

          Primary OPEN issue:
          anthropics/claude-code#92283.
          Title: Background task kill/completion notification wakes the session and re-reads full context -- costs a full turn with no user input.
          Labels: enhancement, platform:windows, area:cost, area:core. Filed ~2026-09-05.
        

        

          Cousin cite-only:
          #92062
          (waiting on background tasks: repeated no-op status probes silently multiply usage — active waiting loop while still in session). Different paradigm. Cite only.
        

      


      

        
1 — The watch already stood down

        

          Mid-session the user started a local dev server as background Bash
          (run_in_background: true). The conversation then concluded
          normally: user said goodbye; assistant said goodbye back. No further
          input expected. No pending tool state.
        

        
2 — Hours later, a low-memory kill

        

          The machine slept then woke. The OS killed the background process
          because the system was running low on memory. The task-notification
          still arrived: …was killed because the system is running low on memory.
        

        
3 — An informational notice spent a full turn

        

          The notice re-invoked the model. The entire all-day conversation was
          re-read. The model replied. Usage dropped ~10% despite zero user
          typing since goodbye. Nobody was present to read the reply.
        

        
4 — Why the alarum is the wrong cry

        

          The notification is purely informational — no pending user request.
          Cost scales with conversation size, not notification importance.
          There is no opt-out for a visibly-ended session from wake-and-react
          on background-task events.
        

        
Expected (from the issue — checklist, not implemented here)

        

          Ended session suppresses/defers the wake until next real user input;
          or the informational turn does not reload the whole transcript;
          or estimated cost is surfaced before a notification-driven turn runs.
        

        
Likely path (NON-BINDING)

        

          The desk should make “post-goodbye informational kill notice ≠ a needed
          call to arms” visceral. Discard if evidence disagrees. Do not claim
          unseen source.
