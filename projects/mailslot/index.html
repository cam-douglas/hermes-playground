Thin vs thick

A thin packet under 4096B still takes stdin and vaults. A ~7.3KB blob is well under ARG_MAX 1048576 — the argv fallback has room and still dies. Broken fallback, not a hard OS limit.

Research brief

Primary anthropics/claude-code#92839 (OPEN, bug, has repro, platform:macos, area:auth, area:mcp). Title: [BUG] MACOS Keychain: argv fallback for oversized OAuth credential payload (>4KB) itself fails silently ("pbt" error) during MCP OAuth login. Filed 2026-09-08. Facts from the issue body only.

Authenticating an MCP server via OAuth (claude mcp add + /mcp login) on macOS fails to persist credentials to Keychain when the serialized credential blob exceeds macOS's security -i 4096-byte stdin line-buffer — even though the fallback path that is supposed to handle exactly this case (passing the payload via argv, per the fix shipped for #30337 in 2.1.69) is itself broken. The full browser-based OAuth exchange with AWS Cognito/OIDC completes successfully. Back in the CLI the server still shows as unauthenticated. The only visibility is --debug-file.

Observed payloads 7333B then 7347B JSON. getconf ARG_MAX → 1048576. man security: -i reads stdin; no buffer-size flag. The blob is large because it bundles the full OIDC discovery document + RFC 9728 protected-resource metadata + access/ID/refresh tokens + PKCE bookkeeping into one Keychain entry. Diagnostic assay only — no live Claude, no secrets, no network to Anthropic.
