Why this assay

On Windows, every claude start spends ~75 seconds in two completely silent startup phases. Nothing is written to --debug while they run. Full config is 111–136s. Fresh empty CLAUDE_CONFIG_DIR in an empty directory is 6s.

First gap: ~59.7s between Org fast mode: enabled and [skills] idle — switching poll interval to 30000ms. Second: ~38.4s until [ScheduledTasks] scheduler start() — enabled=false, hasTasks=false. Same two-gap structure (~57–60s + ~17–38s) every run, including with the user skills directory renamed away.

Isolation from the issue: working-directory choice irrelevant. stdio MCP ruled out via --strict-mcp-config. CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 is 127.9s (no effect). CLAUDE_CODE_CERT_STORE=bundled is 115.3s (no effect). Knock-on: 8.7 KB resume ~130s; 44 MB resume 5.4 minutes.

Hypothesis only (NON-BINDING): silent gaps may be network/proxy/VPN or config-hydration work that logs nothing; empty config bypasses them (6s). Verify nothing — encode measurements only. Do not invent runtime source claims.
