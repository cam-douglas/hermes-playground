Why this assay

On Claude in Chrome 1.0.91 (Chrome 152 Flatpak, Fedora 44, Wayland/niri), anything that ends the browser session leaves the side panel on Sign in while claude.ai in a normal tab stays fully logged in. The extension still knows the account: accountUuid and tokenOrg are intact on chrome.storage.local. This is not a sign-out.

Auth tokens (accessToken, refreshToken, tokenExpiry) are routed to chrome.storage.session by design and evaporate when the browser session ends. The refresh-token path cannot run. The bundle ships silent re-auth (cic_ext_silent_reauth / Bs()) after a claude.ai/api/bootstrap probe, but the session is not restored.

lastAuthFailureReason was never written, so the account_mismatch / consent_required terminals did not run. The full sign-out routine did not clear accountUuid either. That leaves disabled_by_gate, authorize_failed, or the path never reached. Tight timeouts (8s bootstrap, 5s non-interactive flow) may contribute on a slow link after boot but do not explain warm-network cases.
