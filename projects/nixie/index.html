Why this assay

On Claude Desktop for Windows 1.46388.3 (Code tab), a cross-session send_message (ccd_session_mgmt MCP) from a sender whose permission mode is auto is silently discarded. The same message from a bypassPermissions sender delivers. The sender's tool result still reports "Message sent/queued"; the recipient UI may show the message block optimistically; but no user turn is written to the recipient transcript and no model turn runs.

Delivered sends show a Mapping line in main.log within seconds. Dropped sends never get Mapping, then after ~45s (sometimes 90s): peer input … drew no acknowledgement … settled as undelivered. The piece is discarded with no retry.

Decisive A/B: one hand-opened session, same cwd. Auto pings to an idle recipient settled-as-undelivered at 45s; flipping only permission mode to bypassPermissions delivered the next ping instantly and the Mapping line appeared. classifierSummaryEnabled stayed true. 14/14 dropped sends from auto-mode senders; every delivered send from bypassPermissions. 25 settled-as-undelivered events in one main.log across 6 days.

Ruled out: recipient busy/idle, sender model, chip vs hand-opened, fresh CLI, cwd, recipient identity. Unattended auto-mode sessions lose report-backs with a false "sent" result.
