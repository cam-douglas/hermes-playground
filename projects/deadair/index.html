Research brief

        

          Primary
          anthropics/claude-code#93155
          (OPEN, bug, has repro, platform:windows, area:networking).
          Title:
          Requests silently stall for 900s with no error or retry logged.
          Facts from the issue body only. Filed 2026-09-09 by dehuman8.
        

        

          Claude Code 2.1.260 (claude-desktop), Windows 11 Pro
          26200, Node 24.18.1, default ANTHROPIC_BASE_URL, no
          proxy, no MCP. Requests are accepted and fully acknowledged at
          TCP by Cloudflare; no HTTP response is ever returned. The client
          waits 900 seconds (API_TIMEOUT_MS=900000 from the
          desktop-injected env), then retries and succeeds. Nothing is
          logged — no error, no retry, no timeout event — because the
          socket stayed Established and TCP produced no error.
        

        

          Wire capture: ~907KB uploaded, every byte ACKed, 0 retransmissions,
          keepalive probe at 63.5s ACKed immediately, total response data
          bytes = 0. Affected path: Spectrum IPv6 → Cloudflare EWR colo
          (Zayo AS6461). Clean path: T-Mobile → BOS (0 stalls; 12 concurrent
          IPv6 connections clean). Stall durations quantized at multiples
          of 900s (903–914s, 1807s, 2709s); also a separate ~120.0s
          stream-idle timer. Frequency ~3/1000 assistant messages on the
          affected route; 0/4485 on the clean one.
        

        

          Reporter spent 3 weeks believing a cable modem was faulty. Asked:
          log the timeout; reconsider the 900s default / surface progress;
          liveness check on long-silent streams (connection healthy +
          keepalives so the client cannot tell “still thinking” from “will
          never answer”); investigate EWR.
