Research brief

A PreToolUse hook whose command file is not executable (chmod 644) cannot be spawned. Claude Code treats that as a non-blocking failure, so the tool call proceeds — including when the hook's job is permissionDecision: "deny". Guard is off. Only signal is a two-line Permission denied warning once per tool call forever. The warning never names chmod +x. stream-json emits no PreToolUse hook_started/hook_response.

Primary: anthropics/claude-code#94362 (OPEN). Labels: bug, has repro, platform:macos, area:security, area:hooks. Claude Code 2.1.270; macOS 26.6.2 (Darwin 25.6.0), arm64, zsh. Same settings + prompt with chmod 755 correctly denies (DENIED BY GUARD). Hypothesis (issue text, NON-BINDING): a safety control that cannot be executed should not fail open. The message names /bin/sh and Permission denied but never the cause (chmod +x).

Why the pin shears: spawn failure is reported as non-blocking. Headless / SDK use is invisible — no event, no warning, no non-zero exit. Interactive TUI warning is the only surface, and it reads like a sandbox problem.
