Research brief

Desktop (Linux): Keep computer awake while Claude works hold is never released after a re-adopted or stalled Code session, blocking idle suspend for hours. On Linux the hold is a GNOME session-manager inhibitor (app id /usr/bin/claude-desktop, flags 4 = suspend).

Primary: anthropics/claude-code#94420 (OPEN). Labels: bug, has repro, platform:linux, area:desktop. Claude Code 2.1.270; Claude Desktop 1.52386.6; Pop!_OS 22.04; GNOME Shell 42.9; X11. Case 1 (reproduced on demand): quit mid-turn on a remote SSH Code session, relaunch; re-adopt takes a hold at 10:59:05; turn completes at 10:59:31; from 11:00:12 no Code turn is running, yet the hold is never released. Ordinary holds in the same session released after 118 s and 174 s. Earlier unattended: 4h38m (3h24m after finished) ended armed_grace, not idle. Case 2 (observed): session dropped as stalled at 01:56:20; hold id=25 never released; remote-tools-device claims still cycle. Hypothesis (issue text, NON-BINDING): re-adopt and stall paths take a Code-session keep-awake claim but miss the idle-release / stop path that ordinary turns use.

Desired (narrative only): the Code-session claim should be released as soon as no Code session is mid-turn — after a re-adopted turn completes, and after a session is dropped as stalled if nothing else claims it.
