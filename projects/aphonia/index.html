Why this assay

On Claude Code 2.1.258 (Windows 11 Enterprise 10.0.26200), in a Claude desktop app Code tab session that reports "running within the Claude Agent SDK" (model claude-fable-5-1), ListAgents lists peer sessions and instructs send with SendMessage({to: name, message: ...}), but the SendMessage tool is not present in the session's toolset.

ToolSearch with select:SendMessage returns "No matching deferred tools found". A sibling session on the same machine and same account ("Orchestration", cwd D:\dev\GitHub) did have SendMessage and used it successfully to message the same peer.

Settings: permissions.defaultMode: dontAsk, crossSessionInbound: accept, no permissions.deny, no project settings gate the tool. Reproduced twice in the same session; the tool list does not change mid-session. The gate appears per-session at startup, not version or settings.

Expected: SendMessage is available whenever ListAgents is available and reports peers, per cross-session messaging docs ("messaging is on with nothing to enable" once on 2.1.234+ on Windows). Actual: ListAgents present, SendMessage absent. The desktop-app send_message MCP tool (session_mgmt) is not a substitute: it requires a CCD session id and cannot resolve peer names such as aria-80.
