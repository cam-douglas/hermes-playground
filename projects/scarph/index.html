Why this assay

Claude Code 2.1.263, Windows 11 Enterprise, Node v24.19.0, Git for Windows 2.55.0 (bin\bash.exe → usr\bin\bash.exe, MSYS2 bash 5.3.15). Reporter bilbospocketses. Filed 2026-09-06T19:43:06Z. Labels: bug, has repro, platform:windows, area:bash. OPEN.

Wrapper: source snapshot && export TEMP=... && eval '<command with each ' rewritten as '"'\"'"'>' && pwd -P >| cwdfile. Two things go wrong at the node → bash.exe argv hand-off, and both reproduce with plain Node spawning bash.exe directly — this is the transport, not the wrapper.

The -c argument is cut off between 8,181 and 8,190 characters. Bash then reports unexpected EOF while looking for matching ' (or a here-document delimited by end-of-file) and nothing runs. The quote rewrite makes the error line point at the last quote before the cut — a phantom quoting bug. libuv only refuses at 32,767 (ENAMETOOLONG), so ~7.5K–32K fails with no length diagnostic.

Every doubled backslash arrives halved: A\\B → A\B, G\\\\H → G\\H, including inside quoted heredocs. libuv quotes by MS-CRT rules (backslash doubled only before ") while MSYS2 parses \\ inside double-quoted args as escape. Writing the same script to a file and running the file is byte-exact.

Census: 7,815 Bash commands / 37 sessions — 0 shear failures under 8K expanded chars; 25 of 29 at 9K+; plus Python heredoc SyntaxError from the halving. Through the Bash tool the user's command ceiling is lower (~7,000 chars / ~100 lines) because wrapper text and '"'\"'"' expansion share the same ~8K budget.

Repro needs no Claude Code: Node spawnSync of bash.exe -c with script lengths 8100/8180 OK (START+END), 8190+ only START (tail gone, sometimes no error). Same with CLAUDE_CODE_GIT_BASH_PATH unset. Expected: command runs OR the tool says too long. Today: silent shear + misleading quoting error.

Suggested rails from the issue (not claimed implemented): hand the script via stdin or a temp file (bash <file> / bash -s) instead of as a -c argument; failing that, refuse assembled -c over ~8,100 with a clear message.
