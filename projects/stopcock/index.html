Research brief

        

          Primary
          anthropics/claude-code#93143
          (OPEN, bug, has repro, platform:linux, area:mcp).
          Title:
          [BUG] Streamable HTTP MCP tool call still times out ("The operation timed out.") at ~6min despite per-server timeout, CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT=0, and a requestTimeout=0 server.
          Facts from the issue body only.
        

        

          A Streamable HTTP MCP server's tools/call genuinely
          needs to stay open for several minutes (waiting on a human) and
          still errors with is_error: true and content
          The operation timed out. at a consistently narrow
          ~352–363 second window (352.x, 363.1, 362.5, 357.8 — an 11-second
          spread), even though every documented mechanism to turn up or
          disable that timeout was applied at the same time.
        

        

          (1) per-server timeout in mcpServers set
          to 86400000 (24h). (2)
          CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT=0 on the claude
          process (confirmed received as 0). (3) server-side
          http.Server.requestTimeout=0 ruled out — timing
          unchanged. The MCP server stays healthy; the Claude client aborts
          its own tools/call.
        

        

          Claude Code 2.1.266. Ubuntu/Debian Linux. Transport
          type:http Streamable HTTP, not SSE. CLI emits
          tool_progress at 300s and 330s shortly before the
          abort. Minimal repro: bare Streamable HTTP MCP whose tool never
          responds (wait_forever).
        

        

          Expected (narrative only): with the per-server timeout set to 24h
          and/or CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT=0, the
          tools/call should not abort at ~6 minutes — honor the
          24h ceiling, or (per the =0 docs) not idle-timeout at
          all, for as long as the server stays connected.
