Why this assay

On macOS 26.4 Apple Silicon, Claude Desktop Cowork with /development (~300k files) launches an Apple Virtualization VM that accumulates host-side open file descriptors continuously, including while completely idle.

Pressure snapshot: Claude-owned VM ~409,600 fds (~71% of kern.maxfiles, ~130x next-largest). Guest /proc/sys/fs/file-nr ~512, five processes, top process 4 fds, uptime 2 min. Codex/Node ~106k in an earlier snapshot (secondary). Coalition is Claude, not Docker.

Count still climbing 12 hours after the last prompt. Exhaustion → macOS kernel panic → reboot, 1–5x/day if not caught. Cmd+Q Desktop releases descriptors immediately. kill the VM PID (Claude relaunches it). Smaller subfolder also helps. CLI from Terminal with no VM does not exhibit this.

Hypothesis only (NON-BINDING): most likely the virtiofs / shared-folder layer not releasing host handles for files the guest has touched. Verify nothing — encode the issue body only. Do not invent source-code claims.
