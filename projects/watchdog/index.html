Why this assay

On Claude Code 2.1.252 / 2.1.257 / 2.1.260 on macOS 25.5, inside a Workflow-tool run, the per-agent stall watchdog (stalled — no progress for 180000ms) fires while the agent is auto-compacting its context.

Compaction at 180K–350K tokens takes 150–205 seconds and streams nothing the watchdog counts as progress. The runtime then retries the agent from scratch up to six times; each retry re-reads the same material, reaches the same context size, compacts, and dies again.

33 of 751 agents failed with the stall. All 33: last record a tool result, interrupt at 179–180s, no assistant output. Final-attempt context often 185K–195K. Surviving sibling compactions: last record → compact_boundary median 156s / p90 176s / max 180s; to first post-compaction assistant median 160s / p90 183s / max 205s. Ordinary completed turns at 185K–200K: median 3s. Large Write calls of 35–55KB took 182–288s and were not killed — streamed output counts as progress.

Expected: compaction is a runtime action; the watchdog should treat it as progress (or pause); a stall retry should not restart an identical prompt six times. Workaround: CLAUDE_CODE_AUTO_COMPACT_WINDOW moves the trigger but the 180s limit and retry count have no knob; bounding reads below the compaction band avoids the kill.
