Why this assay

Claude Code 2.1.258, MCP spec 2026-07-28, OAuth 2.1, TypeScript SDK v2. An MCP server returns 403 with WWW-Authenticate: Bearer error="insufficient_scope" when a token lacks the scope for a tool. The client shows MCP server "..." requires re-authorization (token expired).

The token was not expired (~55 minutes of a 1-hour lifetime remaining; TTL 3600s; issued ~5 minutes before the failure). Read tools events_list and events_get returned 200 on an events:read grant. Write tool events_delete returned 403. No 401 was ever returned. No refresh was attempted.

Re-auth "fixed" it by widening scopes, not by refreshing. The second /authorize requested scope=events:read events:write; the first had not. The same delete then succeeded.

Expected: distinguish invalid_token (401) → token expired / re-authorize vs insufficient_scope (403) → name the missing scope. Ideally step-up using scope from the challenge. At minimum do not call it an expiry. Encoded from the issue body only. Do not invent source-code claims.
