Why this assay

Claude Code desktop (Code tab), Windows 11 Pro 10.0.22631, PowerShell 7.6.5, Opus 4.5. Reporter tonibunaiasu. Filed 2026-09-06T19:24:56Z. Updated 2026-09-06T19:25:55Z. Labels: bug, has repro, platform:windows, area:sandbox. OPEN.

On Windows, built-in Remove-Item protection blocks a command whenever the command text contains any Windows path with a space, regardless of what is actually being deleted. The guard appears to split the path at the first space and treat the leading fragment as a protected drive root.

The error names a fragment, not a real path: Remove-Item on system path '"C:\Program' is blocked. This path is protected from removal. Leading quote included; cut at the space.

Each repro is a single PowerShell tool call. The deleted file is always a throwaway in %TEMP%. Baseline (Set-Content + Remove-Item on $env:TEMP\probe.txt) passes. Mentioning C:\Python314\python.exe passes. Mentioning C:\Program Files\Git\bin\bash.exe blocks on "C:\Program. Mentioning C:\AI Projects\README.md blocks on "C:\AI — an ordinary user working directory. Putting the spaced path before Remove-Item still blocks, so this is not proximity or line based.

Expected: the guard inspects the argument(s) actually passed to Remove-Item and blocks only if that resolves to a protected location. Actual: the guard scans the whole command text for the verb Remove-Item and anything path-shaped; blocks on the pair; the deletion target is never consulted.

Impact: any project folder with a space makes every cleanup unrunnable. Common hits: C:\Program Files → C:\Program; C:\Users\…\My Documents. Agents drop cleanup; checks silently reuse stale artifacts. The message string protected from removal is in bundled claude.exe under claude_agent_sdk/_bundled/ — product behaviour, not a user hook.

Suggested rails from the reporter (not claimed implemented): resolve actual Remove-Item args against the protected list; if a text pre-filter is kept, do not cut inside quoted paths; do not treat two-segment fragments like C:\AI as drive roots. Encoded from the issue body only. Do not invent runtime source claims. Hypothesis only (NON-BINDING): the Remove-Item guard tokenizes command text on whitespace without respecting quotes and pairs the Remove-Item verb with any path-shaped substring, never consulting the actual AST argument to Remove-Item. Verify nothing.
