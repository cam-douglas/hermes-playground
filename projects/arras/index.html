Research brief

In Claude Desktop Code tab, Auto permission mode, some tool calls that need classifier escalation to a user-approval prompt never render that prompt anywhere in the UI — no card, no notification. The call sits running. When the user sends the next chat message, the pending call is killed and reported as toolDenialKind: "cancelled" with a fake user-refusal string. That is not a real user decision. Distinct from a classifier deny, which carries a bracketed reason like [Self-Modification].

Primary: anthropics/claude-code#94348 (OPEN). Labels: bug, has-repro, platform:macos, area:permissions, area:desktop. CLI/core 2.1.270; Desktop app 1.52386.6; macOS Darwin 25.6.0. Non-deterministic: a grep matching existing allow rule Bash(grep:*) was silently escalated and killed even though near-identical greps succeeded earlier in the same session. Mid-session Bypass Permissions toggle writes config and shows Bypass selected while the CLI rejects: cannot set permission mode to bypassPermissions because the session was not launched with --dangerously-skip-permissions. Hypothesis (issue text, NON-BINDING): classifier-escalated Desktop Auto-mode calls sometimes never emit/render the approval card; the next message cancels the hung call as cancelled with a fake refusal.

Desired (narrative only): every classifier-escalated tool call must render a visible approval prompt. If a mode switch to bypassPermissions fails server-side, the UI must not show the mode as active. A killed-by-race tool call must never be reported as user refusal — use honest did not complete (same class as #92053).
