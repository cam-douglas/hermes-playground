Research brief

        

          Primary
          anthropics/claude-code#92968
          (OPEN, bug, platform:windows, area:auth, area:mcp, area:desktop).
          Title:
          [BUG] Claude Desktop MCP OAuth callback listener uses a hardcoded port 53280.
          Facts from the issue body only.
        

        

          Claude Desktop opens a local listener to receive the OAuth callback.
          The connector uses a hardcoded TCP port, 53280. No
          fallback port. No retry. If the operating system refuses the bind,
          setup stops. The browser consent window does not open.
        

        

          On Windows, Hyper-V, WSL2, Docker Desktop, and the Virtual Machine
          Platform use winnat and hns. These reserve blocks of the TCP
          dynamic port range. Reporter example: Start 53000 Number 1000;
          excluded range 53249–53348 contains 53280. Bind fails
          listen EACCES: permission denied 127.0.0.1:53280.
          No process listens on the port — EACCES, not EADDRINUSE.
        

        

          Claude Code CLI on the same machine does not have this problem.
          The CLI requests an OS-assigned port (port 0). Redirect example:
          http://localhost:44350/callback. Expected: Desktop
          must bind port 0, build the redirect URI from the assigned port,
          and try a different port if a bind fails. Published workaround:
          move the dynamic port range above 53280 then reboot.
