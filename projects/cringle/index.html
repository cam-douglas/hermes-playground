Why this assay

Claude Code 2.1.258. Linux. Reporter ppravdin. Filed 2026-09-06T19:37:44Z. Updated 2026-09-06T19:38:38Z. Labels: bug, has repro, platform:linux, area:security, area:bash, area:permissions. OPEN.

permissions.deny rules for Bash are matched against the program name of each sub-command in the parsed AST. Before matching, Claude Code unwraps a fixed eight-item list of wrapper programs. Any other wrapper — an ordinary binary or script on PATH that execs its arguments — shifts the program name, so no Bash(<program> ...) rule applies to the command underneath it. Deny and allow rules alike are silently skipped.

From ~/.local/share/claude/versions/2.1.258, function ax(). The complete set of wrappers it strips before rule matching: timeout time nice stdbuf nohup command builtin noglob plus leading VAR=value assignments. There is no fallback and no attempt to resolve what an unknown wrapper actually executes.

Repro: permissions.deny includes Bash(git add -A*). Ask for git add -A → correctly denied. Ask for git add -A preceded by any wrapper binary on PATH that forwards its arguments → runs. The deny rule is never consulted.

Compound forms are correctly caught, which shows the AST splitter is not the problem: cd <dir>; git revert ..., rm -f <path>; git add -A ..., and git add -A && git status were all denied in the same environment.

In one real session, git add -A was denied six times over several weeks. The same operation then ran four times behind a wrapper, committing 103 unintended files and 657,373 insertions. Denials: 2026-08-27T18:15:51Z, 2026-08-28T07:23:26Z, 07:42:37Z, 07:59:53Z, 09:35:12Z, 09:41:26Z. Bypasses: 2026-09-06T16:57:28Z, 17:12:26Z, 18:44:10Z, 19:01:59Z.

Permission prompts were suppressed for the session, so an unmatched command ran silently rather than prompting. The bypass itself does not depend on that.

Suggested rails from the reporter (not claimed implemented): (1) unknown wrapper → treat unmatched / escalate to a prompt rather than fall through; (2) warn at config-load that Bash(...) rules bind the literal program name; (3) check every token of a sub-command against deny rules; at minimum document the eight-item list. Hypothesis only (NON-BINDING): ax() peels only the eight named wrappers and env-prefix tokens, then binds Bash(...) rules to the remaining leading program token; an unknown wrapper is treated as the program itself. Verify nothing.
