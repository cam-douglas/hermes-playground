Why this desk

When a plugin updates, the new cache version directory appears to be seeded from the previous version directory before the fetched content is overlaid. Files that are not part of the plugin at all — untracked, gitignored, or written by a session — are carried into every subsequent version and never collected.

One npm install, run once inside a plugin cache directory in August, had been replicated into 13 version directories by early September: 1.2 GB for a plugin whose actual content is ~100 MB. Each version directory's stray node_modules carries the previous version directory's mtime. Nine of thirteen listed rows chain exactly. The copies are real, not hardlinks — distinct inodes, st_nlink = 1.

The plugin's own remote is clean: node_modules is gitignored, untracked, and absent from the default branch (contents API). The plugin declares no hooks and no install scripts. Nothing about the plugin explains the directory's presence — only the copy-forward does. Anything written once — scratch, a log, a credential — becomes permanent self-replicating accumulation. The cache stops being a cache.

Expected: a new version directory contains the plugin's fetched content and nothing else. Either populate it from a clean fetch, or carry forward only paths the plugin declares.
