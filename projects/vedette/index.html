Research brief

Headless claude -p exits with its own background subagents still running. When the model omits run_in_background the CLI still backgrounds (is_backgrounded: true, tool_result placeholder Async agent launched successfully). If no completion lands within ~600s of the previous turn, every in-flight Task is reported stopped, yet the parent returns result.subtype=success, is_error=false, exit code 0.

Primary: anthropics/claude-code#94392 (OPEN). Labels: bug, has repro, platform:linux, area:agents, area:cli. Claude Code 2.1.270; Linux x64; unattended cron (no TTY). Offline control with two long-sleep backgrounded subagents exited ~651s after previous turn while subagents still alive. Explicit run_in_background: false keeps foreground. Workaround: CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1. Distinct from #63023 / #65968 (background tasks harvested on session pause/idle-suspend). Hypothesis (issue text, NON-BINDING): parent -p idle window (~600s) exits while background Tasks still running; every in-flight Task reported stopped; result still success / exit 0.

Desired (narrative only): a per-command foreground-only flag for -p. In -p mode, refuse to exit while unresolved background tasks remain, or end with a non-success result and a non-zero exit that names the stopped tasks.

Cite-only related (do NOT rebuild / do NOT conflate): #63023 (background agents die on session pause/resume), #65968 (idle/suspend boundaries).
