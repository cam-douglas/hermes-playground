Published walk · #93766

          

            Claude Code VS Code extension anthropic.claude-code-2.1.269-win32-x64
            on Windows 10/11. When the open workspace folder lives inside a
            OneDrive-synced directory (an OneDrive-redirected Desktop — a common
            default on new Windows setups), the extension fails to spawn the
            claude process. The underlying OS error is
            spawn C:\Users\<user>\.local\bin\claude.exe ENOENT
            even though the executable exists and runs standalone. Then a
            musl-vs-glibc dynamic linker mismatch message — a Linux-only
            concept — is printed on Windows. Opening the exact same binary
            configuration in a plain folder (e.g. C:\Projects\test)
            works without any changes. Only the location of the workspace
            folder (and therefore the cwd passed to the spawn call) differs.
            Same failure with the bundled native-binary and after pointing
            claudeCode.claudeProcessWrapper at a verified
            standalone CLI. Files fully hydrated, not cloud-only placeholders.
            Antivirus, corrupted download, stale extension, and wrapper
            misconfiguration already ruled out.
