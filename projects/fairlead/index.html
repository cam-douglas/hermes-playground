Why this assay

On Extension Anthropic.claude-code 2.1.261 (also 2.1.259) in VS Code 1.136.1 with a Windows 11 client and a Remote-WSL Ubuntu window, Shift+dragging a file from the VS Code Explorer into the Claude Code panel does nothing. No @mention, no attachment, no error. The same drag works in a local window.

Cause: the webview drop handler accepts only file:// URIs. Remote windows produce vscode-remote:// URIs. Helper eG0 / OJ0 returns null on a non-file scheme, and the drop is discarded silently. Drag detection is scheme-agnostic, so the overlay still appears.

The codeeditors branch prefers resource.external (the vscode-remote:// string) over fsPath. Preferring fsPath would have worked. Suggested normalize: vscode-remote://authority/path → file:///path before existing logic.
