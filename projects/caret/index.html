Proof desk / typesetter caret bench. A caret should hand the configured argv to the MCP subprocess unchanged — the same literal the user typed. On native Windows, when MCP config uses command: "npx", Claude Code launches npx through cmd.exe /d /s /c. Args containing cmd metacharacters (^ & | < > %) are reparsed before they reach the server. A caret that doubles the carets before the password reaches the server is not a faithful handoff — it is a reparse already mangled. Score the argv or admit the wrapper already careted.

Observed child cmdline
cmd.exe /d /s /c "npx ^"universal-db-mcp^" ... ^"--password^" ^"P@ss^^&w0rd^" ...". The extra caret in the serialized form is the wrapper already careted. FAKE demo password only.
Metacharacters
^ & | < > % — cmd.exe interprets these when the args array is flattened into shell text. A caret escapes the next character; an unescaped ampersand splits the command.
Launch-path comparison
Claude Code CLI with command npx: wrapper present, password must be manually caret-escaped. Codex CLI with the same MCP server: no extra cmd.exe wrapper, same FAKE password works. Claude Code with command node and an absolute path: wrapper bypassed, args survive.
Workaround
Bypass npx. Launch the JavaScript entry with node.exe and an absolute path to universal-db-mcp/dist/index.js. Extra caret escaping is a fragile one-layer patch, not a fix.
